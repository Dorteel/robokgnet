# Creating an action frame

With the project environment activated and NLTK corpora installed (see
[creation setup](robokgnet_creation.md)), recreate Bringing with:

```bash
export NLTK_DATA="$PWD/.venv/nltk_data"
python add_action_frame.py --verbnet-class bring-11.3 --schema schemas/bring-11.3.json
```

The pipeline is:

1. Read the actual CMOC task-frame schema. Its properties define the slots.
2. Read exactly the requested VerbNet class, excluding subclass members.
3. Build the minimal `id`, direct `members`, and schema-shaped `frame`;
   unknown slots are null where permitted.
4. Match the exact class and its members against SemLink2 records.
5. Retrieve the matched FrameNet frame: add `framenet_frame`, sorted unique
   `evoking_words` without POS suffixes, explicitly mapped role descriptions,
   and remaining FEs under `additional_frame_elements`.
6. Update only that action ID in `robonet_graph/robokgverbnet_framenet.json`.

The file is a dictionary keyed by action ID. Each value retains exactly these
six fields: `id`, `members`, `framenet_frame`, `evoking_words`, `frame`,
`additional_frame_elements`. Repeating an ID replaces only its entry. Other
actions are preserved, and JSON keys are sorted deterministically. Existing
single-action files are migrated automatically. KnowledgeInterface supports both
containers without changing its public methods and returns all matching actions.

The command reuses `build_verbnet_resource()`, `enrich()`, and `save_action()`.
It builds the intermediate VerbNet entry in memory and writes no intermediate
knowledge file. To recreate the standalone Bringing intermediate as well:

```bash
python verbnet_to_robokgverbnet.py --class bring-11.3 --schema schemas/bring-11.3.json --output robonet_graph/robokgverbnet.json
python verbnet_framenet_enrichment.py
```

The second command also updates only Bringing in the multi-action file, so the
standard rebuild preserves other action entries.

## Later actions

```bash
python add_action_frame.py --verbnet-class <class> --schema <schema>
```

Provide the genuine corresponding CMOC schema and an installed VerbNet class.
The bundled SemLink snapshot is limited; use `--semlink <snapshot.json>` when
additional explicit evidence is needed. Its existing format is an `alignments`
list with `verbnet`, `member`, and `framenet` fields. No mapping is inferred
from the class name. Zero or multiple matched FrameNet frames cause an error
before the output is changed; this command requires a unique matched frame.

Optional `--role-mappings <file>` accepts SemLink's VN-FN role XML. Only links
matching both the exact class and selected frame apply. Missing or ambiguous
role mappings leave slots null. Bringing currently has no applicable role links,
so all its FEs remain under `additional_frame_elements`.

`--output <path>` permits temporary/test outputs. Search is not generated by this
change, and there is no new schema, alignment, or corpus download.

Tests (all writes use temporary files):

```bash
python -B -m unittest discover -s tests -p 'test_add_action_frame.py' -v
```
